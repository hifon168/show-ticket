# 真实收款接入说明（从"演示"到"真卖票"）

> 本文基于 `server/src/services/payment/*` 与 `server/src/routes/pay.js` 的实际代码梳理。
> 结论先行：**代码已内置真实支付通道（微信 V3 / 支付宝），默认是 test 模拟模式；切到 real 并配好密钥即可联调收款，但这不是"接上就收钱"——还差商户号、密钥、公网 HTTPS 回调和全套经营资质。**

## 二、技术接入步骤（要收钱先做这些）

### 1. 申请企业支付商户号（必须企业主体，个人不行）
- **微信支付商户平台**：用营业执照 + 法人实名注册，类目选「票务」相关；拿到 `APPID / 商户号(MCHID) / APIv3 密钥 / 证书序列号 / API 证书私钥 / 平台证书`。
- **支付宝开放平台**：同理注册网页/移动网站支付，拿到 `APPID / 应用私钥 / 支付宝公钥`。

### 2. 配置 `server/.env`
```bash
PAYMENT_MODE=real

# 微信支付 V3
WX_APPID=你的appid
WX_MCHID=你的商户号
WX_APIV3_KEY=你的apiV3密钥
WX_SERIAL_NO=商户API证书序列号
WX_PRIVATE_KEY=-----BEGIN PRIVATE KEY-----...（PKCS#8）
WX_PLATFORM_CERT=-----BEGIN CERTIFICATE-----...（平台证书，务必配置）
WX_NOTIFY_URL=https://你的域名.com/api/pay/notify/wechat

# 支付宝
ALIPAY_APP_ID=你的appid
ALIPAY_PRIVATE_KEY=-----BEGIN PRIVATE KEY-----...
ALIPAY_PUBLIC_KEY=-----BEGIN PUBLIC KEY-----...
ALIPAY_NOTIFY_URL=https://你的域名.com/api/pay/notify/alipay
ALIPAY_RETURN_URL=https://你的域名.com/api/pay/return/alipay
```

### 3. 服务器必须公网 HTTPS，且回调地址可达
- 真实支付回调（`/api/pay/notify/*`）由微信/支付宝服务器主动访问，**必须是公网可访问的 HTTPS 地址**。
- 微信 Native 返回 `code_url` 生成二维码；支付宝 wap 返回跳转 URL。

### 4. 联调验证
- 微信可用「沙箱」或小额（0.01 元）真实订单验证下单 + 回调落库。
- 支付宝用「沙箱环境」验证。
- 验证订单在 `orders` 表被正确置为已支付（`orderPaid.markOrderPaid`）。

## 三、⚠️ 上线前必须修的安全点

1. **微信回调验签**：当前 `wechatGateway.js` 在**未配置 `WX_PLATFORM_CERT` 时会跳过验签**（仅解密、返回 true 并告警）。生产环境必须配置平台证书，否则存在伪造回调、恶意置订单已支付的风险。
2. **私钥格式**：`WX_PRIVATE_KEY` 须为 PKCS#8（以 `BEGIN PRIVATE KEY` 开头）；支付宝私钥同理。
3. **金额处理**：微信已做 元→分（`Math.round`），支付宝 `toFixed(2)`，无需额外处理。
4. **HTTPS + 防重放**：真实通道建议补充通知幂等（同一 `out_trade_no` 重复通知不重复发货/出票）。

## 四、合规前置（真卖票的硬门槛，比技术难得多）

> 纯演示不收款无需这些；一旦真收钱，下列资质几乎缺一不可，且多为前置审批。

- **ICP 经营许可证（经营性 ICP 证）**：在线售票收款属经营性互联网信息服务，**必须办**。且要求营业执照经营范围含「第二类增值电信业务 / 经营电信业务」等表述 → 你公司「北京磐石引擎科技有限公司」若不含，需**先变更执照增项**，否则证办不下来。
- **营业执照经营范围增项**：增加票务代理 / 增值电信业务相关类目。
- **营业性演出许可证**：若你**自己主办演出并售票**，需文旅部门审批；若为票务代销平台，性质不同但仍受票务经营监管。
- **真实微信/支付宝商户号**：企业主体 + 对公账户 + 类目匹配（票务）。
- **税务与发票**：卖票须开票（电子发票），涉及增值税等。
- **购票实名**：演出票实名制（身份证核验），需对接实名核验。
- **资金结算合规**：票款预收、与主办方结算、资金监管，票务为强监管行业。
- **不能用"纯演示备案"**：需走完整经营性备案流程（含 ICP 证）。

## 五、结论

- **技术上**：真实支付骨架已具备（约占 80%），主要工作是「申请商户号 + 填密钥 + 切 real + 联调 + 补平台证书」，不是重写。
- **合规上**：真卖票是强监管经营行为，ICP 经营许可证 + 执照增项 + 票务/演出资质 + 真实商户号 + 税务实名等是主要成本（数月级），远大于技术接入。
- **建议**：若仅为演示支付流程，`test` 模式已足够；若真要经营，先评估资质可行性（尤其票务强监管），再投入技术联调。
